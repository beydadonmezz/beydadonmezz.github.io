# beydadonmezz.github.io

Portfolio of Beydanur Dönmez plus landing, privacy and support pages for her iOS games.
Next.js (App Router, static export) · Tailwind CSS 4 · Motion · Lenis. Deployed to GitHub Pages by
`.github/workflows/deploy.yml` on every push to `main`.

```bash
nvm use            # Node 22
npm install
npm run dev        # http://localhost:3000
npm run build      # static site in ./out
```

## Add a project

1. Put a cover image in `public/projects/<slug>.webp` (max 1600px wide, e.g.
   `sips --resampleWidth 1600 in.png && cwebp -q 78 in.png -o public/projects/<slug>.webp`).
2. Add an entry to `src/data/projects.ts` where you want it to appear (the array order is the display order):

```ts
{
  slug: "my-project",
  name: "My Project",
  description: "One sentence about what it is.",
  url: "https://example.com",
  category: "web",            // "web" | "mobile" (App Store links are "mobile")
  award: "Awwwards HM",       // optional badge
  image: "/projects/my-project.webp",
  width: 1600,
  height: 804,
},
```

## Add a game

1. Copy assets into `public/games/<slug>/`: `icon.png` (1024px, used for social previews),
   `icon-512.webp` (shown on the site) and `screen-1.webp`… (store screenshots, ~800px wide).
   Then run `sh scripts/game-image-variants.sh` to create the smaller `icon-128/256.webp` and
   `screen-N-480.webp` variants the pages serve via `srcset` (the build fails if one is missing).
2. Add an entry to `src/data/games.ts`. The landing page `/<slug>/` is generated automatically.
3. Put the game's published privacy / terms / support URLs in `legal` (Turkish versions under
   `legal.tr`). This site only links to them: legal pages are never copied into this repo, so the
   pages submitted to App Store Connect stay the single source.
   Exception: LINGRID's legal pages live HERE under `/lingrid/` but are generated in the app repo (see "LINGRID legal pages").
   Exception: a game whose legal pages live HERE (Sledpaws and Snugdoku, since 2026-10-28; Quiltdoku until it was
   retired). Snugdoku's `src/data/legal/snugdoku.tsx` is generated by the Snugdoku repo's `legal/build.py`: edit the
   text there, not here.
   Its content is in `src/data/legal/<slug>.tsx`, registered in `src/data/legal/index.ts`, and served at
   `/<slug>/privacy/`, `/<slug>/terms/` and `/<slug>/support/`, plus `/<slug>/tr/privacy/` ... for the Turkish
   versions in `tr` (routes in `src/app/[game]/`, shared by `src/lib/legal-route.tsx`; only the pages a game has
   are generated). `legal` then holds those site paths. These pages are the single source for that game (App
   Store Connect, Play Console, AdMob and the app link to them), so keep their URLs and section ids stable and
   update the "last updated" date with every change.
4. When the game goes live, set `appStoreUrl` to its App Store link. While it is `null` the page shows a
   disabled "Coming soon to the App Store" button.

Theme colours (`theme.accent`, `theme.secondary`) come from the app icon; `accent` must stay readable on
the near-black background.

## Build checks

`npm run build` runs two guards after `next build` and fails (so nothing deploys) if either fails:

- `scripts/check-counts.mjs`: the project counts rendered on the home page agree
  (heading = All = Web + Mobile + Games, and "Show all N"). Games count as projects. All counts
  come from `countProjects()` in `src/lib/project-counts.ts`.
- `scripts/check-assets.mjs`: every local `src` / `srcset` in the built HTML exists, and so does every page listed
  in `out/sitemap.xml` (this covers the static Fishburg pages in `public/fishburg/`).
- `scripts/check-app-ads.mjs`: `out/app-ads.txt` exists with the exact DIRECT lines for AdMob
  (`pub-6308223268641775`), Unity Ads and Liftoff Monetize, and `out/` has no `lingrid-site/`, `fishburg-site/`
  or `snugpath-site/` folder (self-tested).

## Things that must keep working

- `public/app-ads.txt` is served at `/app-ads.txt`. AdMob and the mediation networks read it because this domain
  is the Marketing URL of the apps in App Store Connect (and the developer website of their Play listings). It is
  one file for all apps: keep every line, and add a network's published block when a game starts using that
  network (Unity Ads and Liftoff Monetize since Snugpath; Mintegral once its account is approved, see Snugpath's
  docs/ADS.md). Don't remove it.
- **The `lingrid-site`, `fishburg-site` and `snugpath-site` repositories must stay published.**
  `lingrid-site` no longer holds LINGRID's legal pages (they moved here, see "LINGRID legal pages" below), but it stays
  published: its `/`, `/privacy`, `/terms`, `/support`, `/indir`, `/tr/…` are permanent redirect stubs to the new
  `/lingrid/…` URLs (old store listings, the shipped app and AdMob still link to them), and its `app/**` files are the
  JSON the shipped app downloads (min-version, errata, packs, d2): never unpublish, redirect or rename them.
  `fishburg-site` is the same since 2026-10-28: its pages (`/`, `/privacy/` incl. `#choices`, `/terms/`, `/support/`,
  `/delete-account/`, `/tr/…`) redirect to `/fishburg/…` (see "Fishburg pages" below), and App Store Connect, Play
  Console, AdMob's consent message and older app builds still point to them. App Store Connect points to
  `https://beydadonmezz.github.io/snugpath-site/privacy`, `/terms`, `/tr/gizlilik`, `/tr/kosullar`.
  GitHub Pages serves those project repos on their paths ahead of this repo. Don't unpublish or rename them, and
  don't create `lingrid-site/`, `fishburg-site/` or `snugpath-site/` folders here.
- Bubble Sway and Puzzle Numbers publish their legal pages on their own domains
  (`bubblesway.app`, `puzzlenumbers.app`).

## LINGRID smart link

`https://beydadonmezz.github.io/lingrid` (and `/lingrid/`) is a smart store link:

- iPhone / iPad / iPod (and iPadOS with a desktop UA: `Macintosh` + `maxTouchPoints > 1`) go straight to the App Store,
  Android goes straight to Google Play (`location.replace`, in-app browsers of Instagram, TikTok and Facebook included).
  Everything else (computers) sees the Turkish landing page with both store buttons and a QR code.
- The redirect is a small inline script in the HTML of that one page (`redirectScript` in `src/lib/lingrid-links.ts`,
  rendered by `src/components/LingridLanding.tsx` for `lang="tr"` only). It also checks `location.pathname` is exactly
  `/lingrid`, so it can never act elsewhere. Never redirected: `/lingrid/en/` (English page), any other path under
  `/lingrid/`, every other game page, `/lingrid-site/*` (separate repo) and links given to the stores.
- No cookies, no analytics, no third-party code or requests. Without JavaScript the two buttons are plain links.
- Source tracking: `?s=` with `ig, fb, tt, bio, ig-ad, fb-ad, tt-ad, qr` (anything else = no source).
  App Store: `https://apps.apple.com/app/apple-store/id6815554304?pt=<PT>&ct=<source>&mt=8` (no `ct` without a source).
  Google Play: `...details?id=com.beyda.lingrid&referrer=<urlencoded utm_source=<source>&utm_medium=social&utm_campaign=launch>`
  (plain details URL without a source). The static buttons get the same targets once the DOM is ready.
- **Provider token:** `APP_STORE_PROVIDER_TOKEN` in `src/lib/lingrid-links.ts` (placeholder `PT_TOKEN_PENDING`).
  Replace it with the real App Store Connect `pt` before shipping; it feeds the redirect, the buttons and nothing else.
- The QR code is rendered at build time (dev dependency `qrcode`) and encodes `https://beydadonmezz.github.io/lingrid?s=qr`.
- The Turkish copy lives in `LingridLanding.tsx`; the English copy comes from the `lingrid` entry in `src/data/games.ts`.

## LINGRID legal pages (exception: hosted here, generated elsewhere)

LINGRID's privacy policy, terms and support pages are served from this repo under `/lingrid/`:

| URL | File |
| --- | --- |
| `/lingrid/legal` (hub) | `public/lingrid/legal.html` |
| `/lingrid/privacy`, `/lingrid/terms`, `/lingrid/support` | `public/lingrid/{privacy,terms,support}.html` |
| `/lingrid/tr/gizlilik`, `/lingrid/tr/kosullar`, `/lingrid/tr/destek` | `public/lingrid/tr/{gizlilik,kosullar,destek}.html` |

- **Do not edit these files by hand.** They are generated by `legal/build.py` in the private LINGRID app repo (single
  source, also feeds the in-app copy) and copied here with `bash scripts/publish-legal-web.sh <this clone> [--push]`
  (run in the app repo). Next copies `public/` to `out/`, and GitHub Pages serves `privacy.html` at `/lingrid/privacy`.
- They are plain static HTML and must never contain the phone store redirect: that script lives only in the
  `/lingrid` main page (see "LINGRID smart link"). The `[game]` route only renders `/lingrid/` and `/lingrid/en/`, so
  there is no collision with these files.
- The old `lingrid-site` addresses redirect here (meta refresh + canonical). Publish order after a legal change: this
  repo first, then `scripts/publish-legal.sh` in the app repo (lingrid-site stubs + app data).
- **App data mirror:** `public/lingrid/app/**` (served at `/lingrid/app/...`) is an exact copy of the app's data files
  (min-version, errata, packs, d2). Shipped app versions still fetch them from `lingrid-site/app/` (a stub cannot
  redirect a fetch), the next app release switches to this base. Every data publish must run BOTH scripts of the app
  repo: `scripts/publish-legal-web.sh` (this repo) and `scripts/publish-legal.sh` (lingrid-site). Never redirect or
  hand-edit these files.

## Fishburg pages (static, copied from the Fishburg repo)

`/fishburg/` and its privacy, terms, support and delete-account pages (English, and Turkish under `/fishburg/tr/`) are
plain static HTML in `public/fishburg/`. Their single source is the `site/` folder of the Fishburg repo, which also
tests them against the app; copy them with the commands in that folder's `README.md` and never edit them here. The
entry in `src/data/games.ts` sets `staticSite`, so `app/[game]` generates no page for Fishburg, links to it are plain
`<a>` (`GameLink`), the sitemap lists every page, and `npm run build` fails if one of them is missing from `out/`.
